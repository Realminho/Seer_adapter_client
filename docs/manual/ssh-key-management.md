# SSH 키 생성 및 관리 매뉴얼

이 문서는 SSH 키를 만들고 원격 장비에 등록하는 방법, 키의 패스프레이즈 입력을
줄이는 방법, 등록된 키를 해제하는 방법을 설명한다.

SSH 계정의 로그인 **패스워드**와 개인 키를 보호하는 **패스프레이즈**는 서로
다르다. 보안상 가장 권장하는 방식은 패스프레이즈가 있는 키를 만들고
`ssh-agent`에 세션당 한 번 등록하는 것이다. 무인 실행 등 꼭 필요한 경우에만
패스프레이즈 없는 전용 키를 사용한다.

## 1. 패스프레이즈 없는 새 키 만들기

기존 기본 키를 덮어쓰지 않도록 용도를 나타내는 별도 파일명으로 만든다.

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_amr -N "" -C "amr-access"
```

- `-t ed25519`: Ed25519 형식의 키를 만든다.
- `-f`: 키 파일 경로를 지정한다.
- `-N ""`: 빈 패스프레이즈를 지정한다.
- `-C`: 키를 식별할 설명을 붙인다.

다음 두 파일이 생성된다.

```text
~/.ssh/id_ed25519_amr      # 개인 키: 외부에 전달하지 않음
~/.ssh/id_ed25519_amr.pub  # 공개 키: 원격 장비에 등록
```

개인 키 권한을 확인한다.

```bash
chmod 600 ~/.ssh/id_ed25519_amr
```

패스프레이즈 없는 개인 키 파일이 유출되면 즉시 접속에 악용될 수 있다. 이 키는
필요한 장비와 계정에만 등록하고, 공유 PC나 동기화 폴더에 보관하지 않는다.

## 2. 기존 키의 패스프레이즈 제거

기존 개인 키의 패스프레이즈만 제거하려면 다음 명령을 실행한다.

```bash
ssh-keygen -p -f ~/.ssh/id_ed25519
```

현재 패스프레이즈를 입력한 뒤 새 패스프레이즈와 확인 입력을 모두 빈 값으로 두고
Enter를 누른다. 공개 키와 원격 장비의 등록 내용은 바뀌지 않는다.

## 3. 원격 장비에 공개 키 등록

새로 만든 키는 기존 키와 별개의 키 쌍이다. 따라서 이 키로 접속할 원격 장비마다
새 공개 키를 다시 등록해야 한다. 한 장비에 등록했다고 다른 장비에도 자동으로
등록되지는 않는다.

`ssh-copy-id`를 사용하면 원격 계정의 `~/.ssh/authorized_keys`에 공개 키가
추가된다. 이 단계에서는 원격 계정의 로그인 패스워드를 한 번 요구할 수 있다.

```bash
ssh-copy-id -i ~/.ssh/id_ed25519_amr.pub ucore@192.168.3.222
```

등록 후 새 터미널을 열어 접속을 확인한다. 기존 SSH 세션은 확인이 끝날 때까지
종료하지 않는다.

```bash
ssh -i ~/.ssh/id_ed25519_amr ucore@192.168.3.222
```

새 키로 정상 접속되는 것을 확인하기 전까지 기존 키와 기존 SSH 세션을 유지한다.

### 접속할 때 `-i` 생략

매번 개인 키 경로를 지정하지 않으려면 로컬 PC의 `~/.ssh/config`에 다음 항목을
추가한다.

```ssh-config
Host jibot222
    HostName 192.168.3.222
    User ucore
    IdentityFile ~/.ssh/id_ed25519_amr
    IdentitiesOnly yes
```

이후에는 설정한 별칭으로 접속한다.

```bash
ssh jibot222
```

패스프레이즈가 없는 키는 복호화를 위한 `ssh-agent` 등록이 필수는 아니다.

## 4. 패스프레이즈가 있는 키를 `ssh-agent`에 등록

패스프레이즈를 유지하면서 반복 입력을 피하려면 에이전트를 시작하고 키를
등록한다. 패스프레이즈는 등록할 때 한 번만 입력한다.

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

등록된 키를 확인한다.

```bash
ssh-add -l
```

이후에는 평소처럼 접속한다.

```bash
ssh ucore@192.168.3.222
```

macOS에서는 로그인 키체인에 저장할 수 있다.

```bash
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
```

## 5. `ssh-agent`에서 키 등록 해제

현재 에이전트에서 특정 키만 해제한다.

```bash
ssh-add -d ~/.ssh/id_ed25519
```

현재 에이전트에 등록된 키를 모두 해제한다.

```bash
ssh-add -D
```

이 명령들은 에이전트 메모리의 등록만 해제한다. 로컬 키 파일과 원격 장비의
`authorized_keys`는 삭제하지 않는다.

## 6. 원격 장비에서 접속 권한 제거

먼저 제거할 공개 키의 지문을 로컬에서 확인한다.

```bash
ssh-keygen -lf ~/.ssh/id_ed25519_amr.pub
```

원격 장비에 접속해 `authorized_keys`를 백업하고, 해당 공개 키 한 줄만 삭제한다.

```bash
ssh ucore@192.168.3.222
cp ~/.ssh/authorized_keys ~/.ssh/authorized_keys.bak
nano ~/.ssh/authorized_keys
```

다른 사용자의 키 줄을 함께 지우지 않도록 주의한다. 편집 후 새 터미널에서 해당
키의 접속이 거부되는지 확인한다.

```bash
ssh -o IdentitiesOnly=yes -i ~/.ssh/id_ed25519_amr ucore@192.168.3.222
```

다른 키나 패스워드 인증이 허용된 서버에서는 일반 `ssh`가 성공할 수 있으므로,
위와 같이 `IdentitiesOnly=yes`와 확인할 키를 명시한다.

## 7. 로컬 키 파일 삭제

원격 장비에서 키를 제거하고 다른 접속 수단이 동작하는 것을 확인한 뒤에만 개인
키와 공개 키 파일을 삭제한다.

```bash
rm ~/.ssh/id_ed25519_amr ~/.ssh/id_ed25519_amr.pub
```

키 파일 삭제는 되돌리기 어렵다. 아직 등록된 원격 장비가 있거나 유일한 접속
수단이라면 먼저 백업하거나 대체 키를 등록한다.

## 8. 권장 선택

일상적인 수동 접속에는 패스프레이즈가 있는 키와 `ssh-agent` 조합을 사용한다.
패스프레이즈 없는 키는 자동화 전용으로 분리하고 권한과 사용 대상을 최소화한다.
서버의 일반 패스워드 인증을 켜는 것은 무차별 대입 공격에 노출될 수 있으므로,
키 인증을 사용할 수 있다면 우선 선택하지 않는다.
